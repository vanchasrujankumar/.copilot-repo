# QA Tester Skill

## Overview
Expertise in software testing, quality assurance, and test automation with data-driven and test-driven approaches.

## Core Competencies

### Testing Types
- **Unit Testing**: Individual component testing
- **Integration Testing**: Component interaction testing
- **System Testing**: Complete system testing
- **Acceptance Testing**: User acceptance testing
- **Regression Testing**: Ensuring no functionality breakage

### Testing Levels
- **Component Testing**: Individual modules
- **Integration Testing**: Module interactions
- **System Testing**: Full system validation
- **Acceptance Testing**: Business validation

### Testing Approaches
- **Test-Driven Development (TDD)**: Red-Green-Refactor
- **Behavior-Driven Development (BDD)**: Gherkin syntax
- **Data-Driven Testing**: Parameterized test cases
- **Keyword-Driven Testing**: Action word based

## Test Automation

### Tools & Frameworks
- **Playwright**: End-to-end testing
- **Cypress**: Browser-based testing
- **Selenium**: Web automation
- **JUnit/TestNG**: Unit testing
- **Pytest/Unittest**: Python testing

### Test Frameworks
- **Gherkin**: Feature files with Given-When-Then
- **Page Object Model**: Reusable page classes
- **Custom Frameworks**: Organization-specific

### API Testing
- **Postman**: Manual API testing
- **RestAssured**: Java API testing
- **Pytest-Requests**: Python API testing
- **OpenAPI/Swagger**: API specification testing

## Test Design

### Test Cases
- **Positive Testing**: Valid inputs
- **Negative Testing**: Invalid inputs
- **Boundary Testing**: Edge cases
- **Equivalence Partitioning**: Group similar inputs
- **Decision Table Testing**: Complex logic

### Test Data Management
- **Test Data Generation**: Synthetic data
- **Test Data Sets**: Predefined datasets
- **Data Masking**: Sensitive data protection
- **Test Data Environments**: Isolated environments

## Quality Metrics

### Test Metrics
- **Test Coverage**: Code coverage percentage
- **Defect Density**: Bugs per size unit
- **Test Pass Rate**: Passed vs total tests
- **Mean Time to Detect (MTTD)**: Bug detection time

### Process Metrics
- **Test Cycle Duration**: Time per test cycle
- **Defect Escape Rate**: Bugs in production
- **Test Environment Uptime**: Availability
- **Test Automation Coverage**: Automated vs manual

## Test Strategies

### Test Pyramid
- **Unit Tests**: Many, fast, cheap
- **Integration Tests**: Fewer, slower
- **E2E Tests**: Fewest, slowest, expensive

### Test Matrix
- **Browser Matrix**: Cross-browser testing
- **Device Matrix**: Cross-device testing
- **OS Matrix**: Cross-platform testing
- **Configuration Matrix**: Different settings

## Bug Management

### Bug Lifecycle
1. **New**: Bug identified
2. **Assigned**: Assigned to developer
3. **Open**: Developer working on fix
4. **Fixed**: Fix implemented
5. **Retest**: QA verification
6. **Closed**: Verified fix
7. **Reopened**: Fix didn't work

### Bug Reporting
- **Clear Title**: Summarize the issue
- **Steps to Reproduce**: Detailed steps
- **Expected vs Actual**: Clear comparison
- **Environment**: OS, browser, version
- **Attachments**: Screenshots, logs

## Best Practices

1. **Test Design**
   - Write tests before code (TDD)
   - Use meaningful test names
   - Keep tests independent
   - Test one thing per test
   - Use assertions for validation

2. **Test Automation**
   - Automate regression tests
   - Use page object model
   - Implement test data management
   - Handle flaky tests
   - Maintain test environment

3. **Quality Assurance**
   - Shift left testing
   - Continuous testing
   - Test coverage monitoring
   - Automated test reporting
   - Quality gates

4. **Collaboration**
   - Participate in requirements review
   - Collaborate with developers
   - Document test scenarios
   - Share test results
   - Improve test processes
