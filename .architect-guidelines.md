# Architect & Lead Developer Guidelines

## Optimization Principles

### Performance Optimization
- **Measure first, optimize second** - Profile before optimizing
- **80/20 rule** - Focus on critical 20% that impacts 80% of performance
- **Cache intelligently** - Use appropriate caching strategies (LRU, TTL)
- **Lazy loading** - Load resources only when needed
- **Batch operations** - Minimize round trips with batching
- **Connection pooling** - Reuse database/network connections

### Memory Optimization
- **Object pooling** - Reuse objects instead of creating new ones
- **Stream processing** - Process data in streams, not all at once
- **Memory profiling** - Regular memory usage analysis
- **Garbage collection** - Understand and optimize GC behavior
- **Leak detection** - Proactive memory leak monitoring

### CPU Optimization
- **Algorithm selection** - Choose O(n log n) over O(n²)
- **Parallel processing** - Use multi-threading where appropriate
- **Async operations** - Non-blocking I/O for better throughput
- **Vectorization** - Use SIMD operations when available
- **JIT optimization** - Understand and leverage just-in-time compilation

## Scalable Architecture

### Horizontal Scaling
- **Stateless services** - No session state in services
- **Shared nothing** - Independent, self-contained services
- **Load balancing** - Distribute traffic evenly
- **Auto-scaling** - Scale based on metrics (CPU, memory, queue depth)
- **Service discovery** - Dynamic service registration and discovery

### Data Scalability
- **Sharding** - Distribute data across multiple nodes
- **Replication** - Read replicas for read-heavy workloads
- **CQRS** - Separate read and write models
- **Event sourcing** - Store state as sequence of events
- **Materialized views** - Pre-compute expensive queries

### Resilience Patterns
- **Circuit breaker** - Fail fast when dependencies are down
- **Retry with backoff** - Exponential backoff for retries
- **Bulkhead** - Isolate failures to prevent cascading
- **Timeout** - Set appropriate timeouts for all operations
- **Fallback** - Provide degraded functionality when possible

## Clean Code & Human-Readable Comments

### Commenting Standards
- **Explain why, not what** - Code shows what, comments explain why
- **Business logic context** - Explain business rules and constraints
- **Complex algorithms** - Document non-obvious algorithms
- **Trade-offs** - Document design decisions and trade-offs
- **TODO/FIXME** - Use with dates and owners: `// TODO(2026-05-25): Refactor when X is ready`

### Human-Readable Format
```java
// Good: Explains business rule
// Calculate discount based on customer loyalty tier and purchase amount
// Loyalty tiers: Bronze (0-99 points), Silver (100-499), Gold (500+)
// Discount rates: Bronze 5%, Silver 10%, Gold 15%
// Minimum purchase: $50 for discount eligibility
public double calculateDiscount(Customer customer, double purchaseAmount) {
    // Implementation
}

// Bad: Just repeats code
// Calculate discount
public double calculateDiscount(Customer customer, double purchaseAmount) {
    // Implementation
}
```

### Checkstyle Compliance
- **Naming conventions** - Follow language-specific conventions
- **Line length** - Max 100 characters per line
- **Indentation** - Consistent 2 or 4 spaces (no tabs)
- **Braces** - Consistent brace placement (K&R or Allman)
- **Imports** - Organized imports (standard libraries first)
- **Whitespace** - Consistent whitespace usage

## Monitoring & Observability

### Key Metrics
- **Latency** - P50, P95, P99 response times
- **Throughput** - Requests per second
- **Error rate** - Percentage of failed requests
- **Saturation** - Resource utilization (CPU, memory, disk)
- **Business metrics** - Domain-specific success indicators

### Alerting Strategy
- **Alert on symptoms** - Not on individual component failures
- **Multi-level alerts** - Warning → Critical → Page
- **Runbooks** - Documented procedures for each alert
- **On-call rotation** - Clear escalation paths
- **Post-mortems** - Learn from incidents

## Continuous Improvement

### Technical Debt Management
- **Track debt** - Document technical debt items
- **Prioritize repayment** - Based on impact and effort
- **Regular refactoring** - Allocate time for code health
- **Automated detection** - Use tools to identify debt
- **Team awareness** - Keep team informed about debt

### Knowledge Sharing
- **Architecture decisions** - Document ADRs (Architecture Decision Records)
- **Pattern library** - Maintain reusable patterns
- **Code reviews** - Regular peer reviews
- **Brown bag sessions** - Regular knowledge sharing
- **Documentation** - Keep documentation up-to-date

## Leadership Responsibilities

### Technical Leadership
- **Set standards** - Establish and enforce coding standards
- **Mentor team** - Guide junior developers
- **Review designs** - Participate in design reviews
- **Stay current** - Keep up with technology trends
- **Balance innovation** - Balance new tech with stability

### Project Leadership

- **Manage risks** - Identify and mitigate risks early
- **Communicate clearly** - Regular status updates
