# Global Copilot Instructions

## Core Principles

### 1. Multi-Agent Approach
- **Always use orchestrator** for complex tasks
- **Route to specialist agents** based on context
- **Aggregate results** from multiple agents
- **Enable self-learning** for continuous improvement

### 2. TDD & Quality
- **Write tests first** (Red-Green-Refactor)
- **100% test coverage** required
- **Zero lint issues** - strict code quality
- **Clean code** - SOLID, DRY, KISS principles

### 3. Security First
- **Never expose secrets** in code
- **Use environment variables** for configuration
- **Validate all inputs** for security
- **Follow security best practices**

## Workflow Guidelines

### For Development Tasks
1. **Analyze requirements** with orchestrator
2. **Design solution** with appropriate agents
3. **Write tests first** (TDD approach)
4. **Implement solution** with clean code
5. **Run all tests** and quality checks
6. **Document changes** with conventional commits

### For Architecture Tasks
1. **Use Java Architect agent** for design
2. **Consider scalability** and performance
3. **Apply patterns** from skills directory
4. **Validate with Security Engineer**
5. **Test with DevOps Engineer**

### For Data Tasks
1. **Use Data Engineer agent** for pipelines
2. **Apply data patterns** from skills
3. **Validate data quality**
4. **Test performance** with realistic data
5. **Monitor with observability**

## Agent Selection Guide

### When to use which agent:
- **Full Stack Engineer**: Web applications, APIs, frontend+backend
- **Java Architect**: Enterprise systems, microservices, design patterns
- **DevOps Engineer**: CI/CD, infrastructure, deployment, monitoring
- **Security Engineer**: Security reviews, vulnerability assessment, compliance
- **Data Engineer**: Data pipelines, ETL, data warehousing, analytics
- **QA Tester**: Testing strategies, test automation, quality assurance

### Multi-Agent Scenarios:
- **Complex feature**: Orchestrator → Full Stack + QA Tester
- **System design**: Orchestrator → Java Architect + DevOps + Security
- **Data pipeline**: Orchestrator → Data Engineer + DevOps
- **Security review**: Orchestrator → Security Engineer + relevant specialist

## MCP Integration

### Always use MCP for:
- **External APIs** (GitHub, Jira, Slack)
- **Database operations** (PostgreSQL, MongoDB)
- **Event streaming** (Kafka, EventBridge)
- **Monitoring** (Grafana, Prometheus)
- **Data processing** (BigQuery, Spark)

### MCP Best Practices:
- **Never hardcode credentials**
- **Use environment variables**
- **Implement error handling**
- **Monitor MCP health**
- **Cache when appropriate**

## Testing Requirements

### Mandatory Tests:
- **Unit tests**: All functions/methods
- **Integration tests**: Component interactions
- **E2E tests**: Complete workflows
- **Performance tests**: Load and stress testing
- **Security tests**: Vulnerability scanning

### Test Coverage:
- **100% line coverage**
- **100% branch coverage**
- **100% function coverage**
- **Realistic test data**
- **Independent test execution**

## Code Quality Standards

### Must Have:
- **Descriptive names** (no abbreviations)
- **Small functions** (< 20 lines)
- **Clear comments** for complex logic
- **Consistent formatting**
- **Proper error handling**

### Must Not Have:
- **Magic numbers** (use constants)
- **Code duplication** (DRY principle)
- **Complex conditionals** (simplify)
- **God objects** (single responsibility)
- **Tight coupling** (loose coupling)

## Security Guidelines

### Never:
- **Commit secrets** (.env, credentials)
- **Expose sensitive data** in logs
- **Skip input validation**
- **Use insecure libraries**
- **Ignore security warnings**

### Always:
- **Validate all inputs**
- **Sanitize user data**
- **Use encryption** for sensitive data
- **Implement access control**
- **Audit security regularly**

## Performance Guidelines

### Response Times:
- **Simple tasks**: < 2 seconds
- **Complex tasks**: < 10 seconds
- **Heavy processing**: < 30 seconds
- **Background jobs**: Async with progress

### Resource Usage:
- **Memory efficient** algorithms
- **CPU efficient** processing
- **Network efficient** communication
- **Disk efficient** storage

## Documentation Requirements

### For Code:
- **Function documentation** (parameters, returns)
- **Complex algorithm** explanations
- **Architecture decisions** (ADRs)
- **API documentation** (OpenAPI/Swagger)

### For Users:
- **Setup instructions**
- **Usage examples**
- **Troubleshooting guide**
- **FAQ section**

## Continuous Improvement

### Self-Learning:
- **Capture successful patterns**
- **Learn from user feedback**
- **Optimize agent selection**
- **Improve response quality**

### Knowledge Base:
- **Store reusable solutions**
- **Track performance metrics**
- **Document best practices**
- **Share across agents**

## Emergency Procedures

### If tests fail:
1. **Fix immediately** (no broken builds)
2. **Add regression test**
3. **Document root cause**
4. **Prevent recurrence**

### If security issue:
1. **Rotate credentials** immediately
2. **Fix vulnerability**
3. **Audit for similar issues**
4. **Update security practices**

### If performance issue:
1. **Identify bottleneck**
2. **Optimize critical path**
3. **Add performance tests**
4. **Monitor improvements**
